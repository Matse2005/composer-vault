# Deploying Composer Vault on Laravel Forge

This guide follows the [Forge documentation](https://laravel.com/forge/docs). Where the documentation does not state a detail, the guide says so instead of guessing. The panel steps were checked against the documentation only, not by installing on a Forge server.

## Create the site

1. Create a server with a database (the database is created at server level, in the server's Storage tab under Database) and create a database for the vault.
2. Create a new site for the domain of the vault, with a Git repository. A site created without a repository cannot get one later.
3. In the "Advanced settings" of site creation, set the web directory to `public` (Forge defaults to `/public` for most site types) and choose PHP 8.5. The documentation does not list the offered PHP versions, so check that PHP 8.5 with the sodium extension is available on the server. The version can be changed later on the site's Settings tab.
4. Open the site's Domains tab and request a Let's Encrypt certificate. Let's Encrypt on Forge needs an active Forge subscription. Then use only `https://` addresses. The documentation does not give the exact label of the button that starts the request.

## Environment variables

Open the site's Settings panel and the Environment item, and set at least:

```
APP_ENV=production
APP_DEBUG=false
APP_URL=https://vault.example.com
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=vault
DB_USERNAME=forge
DB_PASSWORD=...
SESSION_SECURE_COOKIE=true
SESSION_SAME_SITE=strict
TRUSTED_PROXIES=
```

`APP_KEY` and `VAULT_KEY` are generated by the install step below. Set `TRUSTED_PROXIES` to the addresses of your load balancer if there is one, and leave it empty otherwise. Set `MAIL_MAILER=smtp` if you want invitation mails and health notifications by email, and enter the host, port and credentials on the Notifications page of the dashboard after the install (they can also be set in the environment, which overrides the dashboard). Without a real mailer the invitation link is shown in the admin interface and nothing is mailed. Everything else (single sign-on, retention, alerts, limits) is set in the dashboard, see [settings](../settings.md).

## Deploy script

Use this deploy script, with `vault:doctor` last so that a deploy that breaks a security check fails visibly. The documentation does not name the tab where the deploy script is edited, so look for it in the site's panel.

```bash
composer install --no-dev --optimize-autoloader --no-interaction
npm ci && npm run build
php artisan migrate --force
php artisan optimize
php artisan vault:doctor
```

Forge's zero-downtime deployments add their own release commands around the script; keep the lines above in the place where your own commands go.

## First install

1. Deploy once. The last line, `vault:doctor`, fails on the first deploy because there is no key and no admin yet. That is expected.
2. Run `php artisan vault:install --no-interaction --name="Your Name" --email="you@example.com"` once from the site's Commands panel (commands run from the site root, have no terminal and a five minute limit). The documentation does not say where a command's output is shown; the command history lists the run and its status.
3. If the install cannot write the `.env` file, it prints the `VAULT_KEY` and `VAULT_KEY_VERSION` lines. Add them in the Environment panel, save, and run the command again. Save the key outside the server at once: without it every credential is lost.
4. Open the one-time link the install prints, choose a password and set up two-factor authentication or a passkey.
5. Deploy again. `vault:doctor` now passes.

## Scheduler

Turn on the Laravel Scheduler toggle in the site's Laravel application panel (the documentation places it in the Overview tab). Forge then runs the scheduler every minute. If you prefer to add it by hand, use Site, Processes, Scheduler, Add scheduled job with `php artisan schedule:run`. The Security status page shows the scheduler heartbeat after a few minutes.
