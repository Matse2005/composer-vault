# Deploying Composer Vault on VitoDeploy

This guide follows the [VitoDeploy documentation](https://vitodeploy.com/docs). Where the documentation does not state a detail, the guide says so instead of guessing. The steps have not been run on a VitoDeploy server yet (see the note at the end).

## Create the site

1. On the server, install the database service and PHP 8.5 with the sodium extension (Services and PHP pages of the server). A site can only use a PHP version that is installed on the server.
2. In the server's Databases section, create a database and, in Database Users, a user linked to that database. The documentation does not say how a database is tied to a site; you enter its details in the environment below.
3. Create a site of the Laravel type for the domain of the vault, with the repository and branch of the vault. For a Laravel site you pick a package manager at creation; the default, NPM, matches the deploy script below.
4. On the site's Settings page, check that the PHP version is 8.5 and that the web directory is `/public`. The documentation does not say what is set at creation, so confirm both.
5. On the site's Domains page, set the SSL method of the domain to "Generate Let's Encrypt Certificate". A domain stays pending until it resolves to the server. In the site's Settings, turn on Force SSL: a certificate alone does not redirect HTTP to HTTPS.

## Environment variables

On the site's Application page, use the "Update .env" button and set at least:

```
APP_ENV=production
APP_DEBUG=false
APP_URL=https://vault.example.com
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=vault
DB_USERNAME=...
DB_PASSWORD=...
SESSION_SECURE_COOKIE=true
SESSION_SAME_SITE=strict
TRUSTED_PROXIES=
```

`APP_KEY` and `VAULT_KEY` are generated by the install step below. Set `TRUSTED_PROXIES` to the addresses of your load balancer if there is one, and leave it empty otherwise. Set `MAIL_MAILER=smtp` if you want invitation mails and health notifications by email, and enter the host, port and credentials on the Notifications page of the dashboard after the install (they can also be set in the environment, which overrides the dashboard). Without a real mailer the invitation link is shown in the admin interface and nothing is mailed. Everything else (single sign-on, retention, alerts, limits) is set in the dashboard, see [settings](../settings.md).

## Deploy script

The deployment script runs in the site's path each time you press Deploy. The documentation does not say where the script is edited and gives a Laravel example without a frontend build, so add the build line yourself. Use this script, with `vault:doctor` last so that a deploy that breaks a security check fails visibly:

```bash
composer install --no-dev --optimize-autoloader --no-interaction
npm ci && npm run build
php artisan migrate --force
php artisan optimize
php artisan vault:doctor
```

The documentation's own example also does `git pull`, `php artisan down` and `up` around the commands; keep those if you use them.

## First install

1. Deploy once. The last line, `vault:doctor`, fails on the first deploy because there is no key and no admin yet. That is expected.
2. Create a command on the site's Commands page with the command `php artisan vault:install --no-interaction --name="Your Name" --email="you@example.com"` and run it. Commands run in the site's root directory as the site's user, and each run is recorded with its output and status. The documentation does not name the run button.
3. If the install cannot write the `.env` file, it prints the `VAULT_KEY` and `VAULT_KEY_VERSION` lines. Add them with "Update .env" and run the command again. Save the key outside the server at once: without it every credential is lost.
4. Open the one-time link the install prints, choose a password and set up two-factor authentication or a passkey.
5. Deploy again. `vault:doctor` now passes.

## Scheduler

In the server's Cron Jobs section, click Create and fill in:

- Command: `php /home/vito/your-domain/artisan schedule:run >> /dev/null 2>&1` (the site path is `/home/vito/<domain>`). Do not put `* * * * *` in the command: Vito adds the frequency.
- User: the site's own user, as the documentation recommends.
- Frequency: every minute. The documentation does not show the value for this.

The Security status page shows the scheduler heartbeat after a few minutes.
